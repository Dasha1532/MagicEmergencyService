# Общие отказы от действий

Пулы хранятся в `data/action_refusal_pools.json`. Они выбираются по действию и причине отказа, не по сотруднику или названию объекта. Соседние отказы одной причины не повторяют одну фразу подряд.

Свойство объекта `frozen_action_refusals` связывает действие с причиной: `repair: frozen_repair`, `physical_move: frozen_force`, `antimagic: ordinary_ice`. Оно используется только при `frozen = true`. Кнопка отказного действия остаётся в меню; обязательный осмотр Бориса по-прежнему выполняется первым. Отсутствие связи не запрещает действие: например, раскалывание льда в ванне должно оставаться допустимым.

Активный `cold_source_active` разрешает антимагию против источника холода. Активное движение, поддерживаемое магией, также остаётся допустимой целью антимагии. Сам по себе уровень спящих чар горгульи не означает, что они поддерживают лёд.

Общее меню проверяет отказ перед отправкой действия контроллеру: показывает реплику текущего сотрудника и не запускает подход, анимацию, таймер или результат. Горгулья и шкаф дополнительно проверяют то же правило при непосредственном вызове симуляции. Для будущего объекта нужно описать применимые ограничения в его свойствах и использовать общее меню, а не создавать отдельный пул.
