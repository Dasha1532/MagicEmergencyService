# Судьба Лунопуха

`lunnopuh_care` — повторное обращение Селесты, а не случайная исходная заявка. `WorldMemory.finalize_job` ставит его в очередь по фактическому свойству `lunnopuh_state = caged` у зеркала. Вернувшийся домой зверёк не создаёт обращение. Публикация на следующий день; если возникло привидение, сначала завершается его заявка, затем проходит ещё один день. Пока доступных Бориса/Грога для перевозки либо Ники с сохранившимся порталом нет, обращение остаётся в очереди. Запреты Селесты на вход учитываются.

Данные и утверждённые реплики: `data/objects/lunnopuh_care.tres`. Начальные свойства зеркала берутся из актуальной памяти мира. Симуляция наследует общие действия `PortalMirrorSimulation`; температурные последствия и отказы не копируются. Борис осматривает Лунопуха и зеркало отдельно. Лилия и Феликс не снимают/навешивают полотно, это делают Борис, Грог и Ника.

Ника возвращает пойманного зверька в открытый портал без полотна. Сначала показан полёт из клетки, затем меняются свойства; рабочая поза сохраняется до исчезновения. Для приюта Борис/Грог подходит к клетке, принимает позу подхвата и исчезает вместе с клеткой. Карточка блокируется на два обычных времени пути, показывает возвращение в офис; отъезд сохраняется. Завершение заявки не переносит время возвращения. Другие умения дают ранее утверждённые отказы; антимагия при отсутствующем портале получает утверждённую реплику об уходе специалистов.

Цель: `returned` или `transferred`, при этом портал закрыт, разрушен либо изолирован. При обоих исходах клетка возвращается на склад после завершения без повторного возмещения клетки и полотна. Цена услуги 300 задаётся данными; новый ущерб и холод учитываются в оплате, старое повреждение не становится новым ущербом. Общий журнал переходов сохраняет виновников и полезные действия. Отзывы соответствуют исходу.

Сцена `LunnopuhCareRoom.tscn` наследует гостиную и столик из `GhostMirrorRoom.tscn`; столик и клетку можно редактировать там либо переопределить в новой сцене. `PetApproach`, `MirrorPhysicalApproach` и `Exit` — положение верхнего левого угла сотрудника. Исходный Y = 205. `LunnopuhTransfer` используется только при полёте; лишний зверёк в клетке не рисуется.

Сохранение версии 33 сохраняет подход, рабочий таймер и фазу переноса/перевозки. После загрузки незавершённая визуальная часть повторяется и применяется один раз; завершённый результат не повторяется. Сохранения версии 32 получают последствие по сохранившемуся зверьку, без изменения старых актов и повторной оплаты. Проверки используют отдельный профиль: `tests/run_portal_mirror_checks.ps1 -TestNames lunnopuh_care_test`.
